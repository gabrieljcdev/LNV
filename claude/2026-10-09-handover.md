## What was built
**Shelf stack card** (`ShelfCard` in `frontend/src/components/Feed.jsx`) — one card for albums, singles and compilations at the old geometry (800×820, padY 90, 390px sleeve, 40px radius). Order: type pill + a coloured pill per place it plays (with track coverage) + Discogs + Buy, artist, italic title, dotted label line, genres (two rows, then "+N"), the big post number with a line under it (it sizes itself to the room left), the full tracklist (track artists bold + linked, a dash before the title, a source chip on every track), post title and description (the description fills the space left and scrolls only when full), byline. Compilations get a contributors line and a wider card (`SHELF_COMP_EXTRA`, 1080px). Replies slide out as a 360px side panel. Mockups: `frontend/mockup4.html` (A–F layouts; A was chosen for everything).
**Track artists** — `post_tracks.artist` (saved from the composer's Discogs track credits and by the gap sweeper); also shown as bold links in spotlight rows. **Spotlights:** "+ add to my feed" now lives in each open release row (footer button removed).
**Listening** — `lib/listening.js`, `ListeningSettings.jsx` (♪ button beside the theme button): tick the services you can play full tracks on; the order ticked is the priority; `pickUrl` chooses each track's link (hand-picked source → your services → own link unless it's a preview you can't use → anything). `TrackPlayer.jsx` loads Spotify through its iFrame API: 30s duration = preview, real length = full (recorded, demotes/promotes Spotify). Saved in the browser and on the account (`users.listening`, `GET/PUT /api/users/me/listening`). YouTube Premium can't be detected (tick-only).
**Compose (+) button** — a zero-size sticky anchor in the feed row: starts 16px in from the first post's lower-left corner, scrolls with it, locks 12px clear of the nav rail (`COMPOSE_LOCK_GAP`).
**Discogs collection + wantlist as private playlists** — username only (public lists), no proof of ownership (`ownership: unverified`; an optional code pasted into the "Profile" box under Discogs Settings → Profile marks it `profile-code`). Backend `services/discogsAccount.js` (import, daily refresh, playable checks, `recordsFor`), routes `/api/discogs-account` (status, link, verify, sync, records, DELETE) and `GET /api/playlists/:id/releases`; tables `discogs_links`, `playlist_releases`; playlist kinds `collection` / `wantlist`. Screens: `DiscogsConnect.jsx` (dialog, post-login prompt, Playlists-drawer strip, profile row), `DiscogsLists.jsx` (the record list; faded "media unplayable" rows). Sharing, inviting, editing, deleting and "show on profile" are all refused for these two lists. Their records' artists/labels/catnos also go into the catalogue DB and crawl queue (`recordRelatedReleases`, Various excluded).
**Names and tabs** — `discogs_names` + `entityNameResolver.js` (Admin shows names, not `#ids`); the Artists and Labels tabs merge in your own Discogs records (private to you) and each row reads "N posts / M in catalogue" (`GET /api/discogs/catalogue-totals`).
**Smaller:** the live-set detector (title + duration only; Remix / Official / "Full Album" titles are releases; stored `post_type` wins in the feed); every Discogs release a pasted link matched is kept (`related_releases`) and its artists/labels crawled; `LNV_DB_PATH` env var to point the backend at another DB.

## How to work with it
- **Test without touching real data:** copy the DB (`better-sqlite3` `.backup()` to the scratchpad), run with `LNV_DB_PATH=<copy>`, and mount only the routes you need on a spare port in a tiny express file. To see signed-in screens in the browser pane: set a fake `lnv_auth` in localStorage *after* the page loads (the load-time session check would clear it), patch `window.fetch` to send `/api/discogs-account|playlists` to the scratch server, and open drawers through React's fiber (`openD3` from `LayoutContext`, the query client from `QueryClientProvider`). Clear the fake auth afterwards. Never use made-up ids in a range real Discogs ids use when cleaning up test rows (an early test deleted real catalogue rows for ids ≥ 9,999,000 — the crawler refilled them).
- **Shell:** long heredocs break the shell tool here — write files with the editor tool and run small Python patch scripts from the scratchpad; mind CRLF (read bytes, normalise, write back the same way).
- **Browser pane:** it is ~800px wide, so wide layouts are cropped; emulate a viewport and pin a card (`position: fixed; left: 0; top: 0; height: 100vh`) to see one at 1:1. Don't accept cookie banners on other sites.
- **Env knobs:** `DISCOGS_IMPORT_MAX_PAGES=1` limits an import (testing); `YOUTUBE_FIRST=1` restores YouTube-first link search.

## Gotchas found
- A start-up migration in `db/database.js` ("every playlist public") runs on every boot — it had made the Discogs lists public with share links; it now skips kinds `collection`/`wantlist`, and `discogsAccount.js` repairs the rows on start. If sharing is ever switched on for them, change both.
- The site's `DISCOGS_TOKEN` belongs to gabriel's own Discogs account: **never use it for writes** on behalf of whoever typed a username.
- `discogs_catalogue_crawl` "stalled" just means no progress for 2h — the one slow worker round-robins hundreds of entities.
- Two accounts can link the same Discogs username (only the profile-code check distinguishes them).
