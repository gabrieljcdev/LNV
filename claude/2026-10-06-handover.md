## Working notes (hard-won, 4–6 Oct)

- **Lint baseline:** `npx eslint src` in `frontend/` is **clean — 0 errors,
  0 warnings** since `4914ef7` (5 Oct). Keep it that way (the JSON
  formatter works; `-f unix` doesn't). React-compiler rules bite: no `setState` in
  effects (use "adjust state during render" or write DOM styles directly),
  no new ref reads in render (pass the ref object down instead), and no
  non-component exports from `.jsx` files (breaks Fast Refresh).
- **Editing:** use Python scripts **written to the scratchpad with the
  Write tool**, not bash heredocs (they mangle quotes; a heredoc once broke
  on an apostrophe). Read and write with `newline=''` and keep each file's
  endings: most frontend files are CRLF, some LF. **Git Bash `sed -i`
  rewrites CRLF to LF**, so avoid it. Make scripts assert each anchor
  matches exactly once, and write only after all edits succeed. Python on
  Windows can't `print` ♥ (cp1252): set `PYTHONIOENCODING=utf-8`.
- **Never do git surgery in the working tree** (stash/partial staging).
  A stash-pop conflict left conflict markers in `Feed.jsx` for seconds, and
  gabriel's dev server showed an error overlay. To split commits, stage
  hunks from `git diff -U0` with `git apply --cached --unidiff-zero`,
  recomputing each hunk's new-side start from the old side plus the net
  lines of the hunks picked before it (git places zero-context hunks by
  that number, and got it wrong once). Verify by building the staged tree in a scratch copy
  (`git archive $(git write-tree) frontend | tar -x`, with a PowerShell
  junction to node_modules; remove the junction with `.Delete()`).
- **Browser pane:** it barely draws frames in the background, so rAF
  animations and smooth scrolls stall, and screenshots often time out, tile
  or crop. Measure with `javascript_tool`. For timed animations, override
  `window.requestAnimationFrame = cb => setTimeout(() => cb(performance.now()), 16)`
  in the page first. Heading text reads in CAPITALS through `innerText`
  where CSS uppercases it. Reset the viewport (`preset: desktop`) after.
- **Signed-in checks:** create a short-lived session from a scratchpad
  `session.mjs` (`createSession(id)` from `backend/services/authService.js`,
  `publicUser`), put `{token,user}` into `localStorage.lnv_auth`, and
  **end the session and remove the file after**. Undo test data (hearts,
  follows, favourites, playlists, bios). Note what was there before.
  gabriel also tests by hand, so **don't revert changes he made himself**
  (his bio and the "dgtjicghjk" playlist are his).
- Users: 1 `lnv_admin` (admin, the "first friend"), 2 `treebeast` (follows

## What changed 4–6 Oct (all on master now)

**The feed model** (replaces 10-03 §8's "main feed + walls"):
- **My feed is the one home** (`03bb644`). Signed in, it opens on **your
  profile card**. Its **Friends' posts** switch shows you + who you follow
  (on) or just your posts (off). That replaced "my wall". The choice is
  stored in `localStorage.lnv_home_friends`. `GET /posts?feed=home[&friends=0]`.
  Your own name opens my feed.
- **First friend** (`0685b7a`): every account follows the first admin
  (lnv_admin) on sign-up, like Tom on MySpace (`authService.befriend`,
  `users.befriended_at`). Unfollowing sticks. **Signed out, the home view
  is the first friend's wall, the "front page".**
- **"everything"** (the old main feed) is a quiet last item in the feed
  menu. The menu is: my feed · playlist feeds · playlists… · walls &
  following… · everything.
- **One post per release; ♥ keeps it** (`2198ddb`, `d548b7f`). `posts.discogs_id`
  is UNIQUE. ♥ on a record's card puts it on your wall and in your
  followers' feeds (`post_joins`, kind 'also'; `POST/DELETE /posts/:id/join`).
  The count is how many people have it. The card reads "admin & you"
  (`alsoPostedBy`). A feed never shows a record twice. **Reposts and track
  hearts are gone.** Tracks keep "+ list". The composer's duplicate
  notice offers "♥ add to my wall".
- Walls and my feed are built from **entries** (posts + joins) in
  `collectionsService.entryPage`, paged by an `"<at>|<id>"` cursor.

**Profiles** (`9998266`, `c8f4196`, `6c0346d`, `03bb644`): `WallCard` in
`Collect.jsx` leads every wall and my feed. `GET /walls/:username/profile`.
- **Everyone sees:** initial (no uploads yet), name, member since,
  posts/followers, bio; **sound** (Discogs *styles* first, broad genres only
  fill gaps); labels / artists / channels led by **♥ favourites**; shown
  playlists; **Following** (who they follow, a friends list to explore).
- **Signed-in visitors also see:** follow, "Followed by … you follow", and
  **In common with you (α ALPHA)**. That's shared records/artists/labels
  from what both chose to post, weighted by rarity, with no engagement
  signals (`inCommon`).
- **The owner also sees:** edit bio, un-♥ favourites, tick which playlists
  show (shown = gets a share link), make a new playlist, private numbers
  ("♥ by N people", replies), View as visitor, and the Friends' posts
  switch on my feed.
- **Favourites** (`6c0346d`): ♥ beside an artist/label/channel name on
  spotlights (desktop + phone), in the artist/label drawers, and by the
  channel on phone live-set cards. Table `favourite_names`,
  `GET/PUT /walls/me/favourites`. They replaced "pin up to 3 labels".

**Reply authors** (`93a2a10`): names open their walls, with a quiet
"+ follow".

**Phone layout** (`6503330`, `c30d697`): below 768px (or a touch screen
under 500px tall) it's a swipe deck of full-screen cards (`PhoneFeed` in
`Feed.jsx`), a bottom nav (`PhoneNav.jsx`), drawers as sheets, and a
single-column composer. **Opening:** the desktop landing (strip / zone /
panel colours) as a layer before the first post. It moves at a fixed 1.2s,
in on a swipe back from the first post and out on a swipe on or a tap
(`PhoneOpening`). gabriel iterated on this a lot; **leave it unless he
asks**.

**Fixes:** "+ list" menu drawn in a portal (cards clipped it); cards take
the latest copy of their post after a refresh (`latestPost`); the old
`favourites` table was dropped; "Hearted tracks" is an ordinary playlist now.
