### Security — TODO before going public

Checked 3 Oct: `.env` is git-ignored and never committed; no
`dangerouslySetInnerHTML` in the frontend; passwords scrypt, session tokens
stored hashed, sign-in/up rate-limited (20 / 15 min); admin routes behind
`requireAdmin`.
- **Dependencies:** `npm audit` — backend 3 (nodemailer HIGH, body-parser and
  qs moderate), frontend 2 HIGH. Run `npm audit fix` in each and retest.
- **Security headers:** none yet. Add `helmet` (CSP allowing the YouTube /
  SoundCloud / Bandcamp / Mixcloud / Spotify embeds, HSTS, frame-ancestors,
  referrer policy).
- **CORS** is hard-coded to `http://localhost:5173` — read the allowed origin
  from `.env` (FRONTEND_URL) for production.
- **Behind a proxy:** set `app.set('trust proxy', …)` so rate limits and the
  log's coarse IP see the real client, not the proxy.
- **Error responses** send `err.message` to the browser — send a generic
  message in production (the full error is already in the admin log).
- **Request size:** `express.json({ limit: '10mb' })` — far more than any post
  needs; drop to ~200kb.
- **Session token in localStorage** (readable by any script if XSS ever
  slipped in). Consider an httpOnly, Secure, SameSite cookie + CSRF guard.
- **Admin hardening:** two-factor sign-in (TOTP) for admin accounts; real
  admin email (still `admin@lnv.test`).
- **Fresh credentials (gabriel, 3 Oct):** in the security pass, ALL admin
  passwords and API keys (Discogs, YouTube, any new ones) get replaced
  fresh. Don't rotate anything piecemeal before then.
- **Accounts:** per-account sign-in lockout (today the limit is per IP);
  check new passwords against known-breached lists (HIBP range API); an
  "email change" flow with confirmation; "sign out everywhere" button;
  delete-my-account + export (UK GDPR).
- **Abuse:** honeypot / bot check on sign-up; report button + admin
  moderation for posts and comments.
- **Embeds:** sandbox / `referrerpolicy` on third-party player iframes.
- **Data:** automatic backups of `backend/db/vinyl_crate.db` (SQLite) off
  the server; the app log keeps emails in `detail` for 30 days — note it in
  a privacy policy.
- **Legal pages:** privacy policy + terms (accounts, emails, logs, embeds).

### Known limits (from 2 Oct's work)

- Spotlight/drawer rows for Discogs **masters** show a "—" type tag for a
  few seconds on first view while their main release is fetched.
- The backup fill attaches a Discogs **artist id when only one artist has
  that name**, even without a label to confirm it (R 417's is unconfirmed).
- **Giant label catalogues** take hours: Columbia ~396k releases, Polydor
  ~244k. Harmless (they take turns in the queue), but a cap (e.g. newest
  10k + search) was offered if the DB size matters.
- Bandcamp and Mixcloud have no pause API: "one player at a time" stops
  them by reloading the iframe (they restart from the top). Bandcamp tracks
  don't autoplay or chain (no API).
