## Verifying in the browser pane — gotchas that cost time

- Open with `preview_start { url: "http://localhost:5173" }`. Emulate sizes
  with `resize_window` (1600×900 and 1920×1080 are the reference screens);
  **re-apply the size after a reload** or measurements read 0×0. Reset with
  preset "desktop" when done.
- The pane is usually **hidden**: CSS transitions, animations, smooth
  scroll, `requestAnimationFrame` and scroll events don't run. So computed
  colours can be stuck mid-fade (read the inline style / CSS var instead),
  the marquee and smooth scrolls don't move, and anything behind rAF won't
  fire. Screenshots are often useless — measure with `javascript_tool`.
- Editing `frontend/mockup.html` auto-opens a `file://` tab that can't
  load it (blank). Use the `localhost:5173/mockup.html` tab.
- When writing code through a node script in a bash heredoc, backslashes
  in regexes get eaten (`/\d+/` became `/d+/` three times). For anything
  with regex/escapes, use the Edit tool, or verify the line afterwards.

## Feed design — current state (all in `frontend/src/components/Feed.jsx`)

Card routing (`Feed` render loop): spotlight → `SpotlightCard`;
`isLiveSetPost` (livemix or set-like title) → `LiveSetCard`;
`isAlbumPost` (> 6 tracks) → `AlbumCard`; else `PostCard` (standard
orientation only — the inverted plate-bottom variant is retired). Every card
is wrapped in `FloatSlot` (rounded `FLOAT_RADIUS` 14, `FLOAT_SHADOW`, half
`FLOAT_GAP` (28) either side, `FLOAT_INSET_Y` top/bottom, per-card text ink).

| Thing | Value / where |
|---|---|
| Card width | regular + album `d.cardW` 800; live + spotlight `liveCardWidth()` (video-derived: 805 @900h, 1125 @1080h) |
| Card height | full screen (`FLOAT_INSET_Y` 0) — uncommitted |
| Padding | `DESIGN_BASE.padY` 90 (uncommitted), sides `bandPadX` 32 (album/regular), `LIVE_PADX` 56 (live), `SPOTLIGHT_PAD` 60 |
| Art | `artSize` 390, `artRadius` 40 — regular art, album sleeve, live video, spotlight strip tiles/players all use `artRadius` |
| Type | `DESIGN_BASE` tokens everywhere: artist/title 30px, badge 9px/600, metaline 11px mono, tracks 13px, track numbers 10px mono, desc 13px, numeral 180px/900 @ 0.22 |
| Surface under feed | `FEED_SURFACE` = plain `var(--theme-bg)` (dots removed) |
| Card colours | `getCardBg`: spotlights `--theme-showcase`; idx ≥ `SPECTRUM_START` (3) palette spectrum; first three `var(--theme-bg)` (TRIAL — `POST_BG_CYCLE` dark1/2/3 line is in a comment there) |
| Text ink | `FloatSlot` + `useCardInk` pick light/dark via `bgIsDark` (luminance < 0.18, handles `color(srgb …)`), tones `INK_DARK_BG` / `INK_LIGHT_BG` (≥ 3:1 incl. mid-tone spectrum) |

- **AlbumCard**: top row sleeve (player replaces it when playing) + post
  description beside it; bottom row badges/artist/title/metaline with the
  big numeral under them | two-column tracklist; byline at the bottom.
- **LiveSetCard**: 16:9 screen (play → autoplay embed via `TrackPlayer`),
  name/set line at artist/title sizes, description, badges + year right-
  aligned flush with the video, quiet byline.
- **SpotlightCard**: Studio PIC-style — header name `[count]`, slow sleeve
  strip (`lnv-marquee` in index.css), numbered index list; rows open to the
  tracklist (Discogs masters resolve to their main release), track click
  plays in place; found YouTube links saved in `release_track_links`;
  full-size covers via `/api/discogs/covers` (throttled queue).
- **Playback**: `TrackPlayer` uses the YouTube IFrame API to detect the end
  of a track → album play-through (PostCard, AlbumCard, spotlights).
- Things tried and dropped (don't re-propose without reason): CSS zoom to
  shrink cards; crate spines; record peeking out of the sleeve; top-right
  numeral on albums; media-on-top for plate-bottom cards; white surface;
  white cards; per-card contrasting palette underlay (parked, not dead);
  dot grid surface (removed). BPM/key: dropped entirely.
